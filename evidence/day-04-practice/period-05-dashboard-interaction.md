## (공통·필수) 문제 1 — 6패널을 읽는 순서로 배치

다음 원칙으로 Dashboard를 정돈하세요.

- 첫 행: 전체 규모 Metric
- 가운데: category 비교, 재고 비율, 월별 등록 등 핵심 차트
- 아래: 가격 분포와 정확한 값 Table
- 긴 label이 있는 패널은 넓게 배치
- 모든 패널 제목 표시

### 배치 기록

- Dashboard 제목: **`D4 공통 상품 Dashboard - 한성민`**
  처음 저장 때 자동 생성된 `Dashboard - 쇼핑몰 상품 데이터`가 남아 있어 `Save as`로 기준 형식에 맞게 바꿨다.
- 첫 행 패널: `전체 상품 수`(Metric) / `재고 상태 비율`(Donut) / `카테고리 별 상품 수`(Bar)
- 둘째 행 패널: `가격대별 상품 분포`(Bar) / `월별 상품 등록 분포`(Line)
- 셋째 행 패널: `브랜드별 상품 수와 평균 가격`(Table)
- 가장 크게 배치한 패널과 이유: **`브랜드별 상품 수와 평균 가격` Table**.
  열이 3개(브랜드·상품 수·평균 가격)이고 행이 11개(상위 10 + `Other`)라 좁으면 가로 스크롤이 생긴다.
  숫자를 정확히 읽는 것이 이 패널의 목적이라 잘리면 쓸모가 없다.
- 크기를 늘려 해결한 가독성 문제: 가격 구간 Bar의 아래축 라벨(`100,000 → 150,000` 등)이
  좁을 때 겹쳐 보였다. 폭을 넓히니 다섯 라벨이 모두 온전히 표시됐다.
  Bar 방향을 바꾸기 전에 **먼저 패널 폭을 넓히는 것**이 순서다.
- 제목이 비어 있던 패널과 수정 결과: 패널을 `Save and return`으로 저장하면 제목이
  `Count of records`처럼 자동 표시되거나 비어 있었다.
  각 패널의 `Settings → Show title`을 켜고 업무 언어로 제목을 다시 붙였다.
  현재 **6개 패널 모두 제목이 표시된다.**
- 캡처 파일: `p05-q03-control-reset.png` (Control `Any`, 6패널 전체 배치가 보인다)

## (공통·필수) 문제 2 — category Options list 추가

Dashboard 편집 모드에서 category Control을 추가하세요.

진입 순서: `Add`(안 보이면 `More → Add`) → `New → Controls → Control → Select a field`

- Data View: 공통 `products`
- field: `category`
- type: Options list
- label: `카테고리 선택`

category 하나를 선택한 뒤 두 패널 이상의 값이 바뀌는지 확인하고 `Any`로 복구하세요.

### 전후 기록

- 선택한 category: **`전자기기`**
- 적용 전 Metric: **20,000**
- 적용 후 Metric: **2,500**
- 함께 바뀐 패널 2개: 요구는 2개지만 **6개 패널이 전부 바뀌었다.**

| 패널 | 적용 전 | 적용 후 |
|---|---|---|
| 전체 상품 수 | 20,000 | **2,500** |
| 재고 상태 비율 | true 16,999 / false 3,001 | **true 2,145 / false 355** |
| 카테고리 별 상품 수 | 막대 8개 각 2,500 | **막대 1개**(전자기기) |
| 가격대별 상품 분포 | 7,304 / 4,608 / 2,645 / 2,550 / 2,893 | **181 / 300 / 295 / 330 / 1,394** |
| 브랜드별 Table | 상위 10 + Other | **전자기기 브랜드 5개만** (Auralis 520, MobiCore 516, PixelWorks 505, SoundLab 485, NeoTech 474) |
| 월별 상품 등록 분포 | 최대 1,728 | 최대 약 **250** |

- 관찰: 가격 분포가 **전체와 정반대로 뒤집혔다.** 전체에서는 저가 구간(7,304)이 가장 컸는데
  전자기기만 보면 20만 원 이상 구간(1,394)이 가장 크다.
  Control은 단순히 건수를 줄이는 것이 아니라 **분포의 모양 자체를 바꿔 보여 준다.**
- `Any` 복구 후 Metric: **20,000**
- 정상 여부: **정상.** 적용·해제 모두 즉시 반영됐고 값이 정확히 복구됐다.
  브랜드 Table이 5개로 줄어든 것은 전자기기 브랜드가 5개뿐이라 `Other`가 사라진 것이며,
  520+516+505+485+474 = 2,500으로 Metric과 맞는다.
- 캡처 파일: `p05-q02-control-applied.png`(전자기기 선택), `p05-q03-control-reset.png`(`Any` 복구)

## (진단·필수) 문제 3 — Control·Filter·KQL을 구분하고 초기화

다음 세 방식을 한 번씩 사용하세요. 한 방식을 확인한 뒤 반드시 지우고 다음으로 이동합니다.

1. category Control에서 값 선택
2. `Add filter`에서 `in_stock is false`
3. KQL에서 `price >= 100000`

| 방식 | 입력한 조건 | 적용 전 값 | 적용 후 값 | 해제 방법 | 해제 후 값 |
|---|---|---:|---:|---|---:|
| Control | `카테고리 선택` = `전자기기` | 20,000 | **2,500** | 선택기를 `Any`로 되돌림 | **20,000** |
| Filter | `in_stock : false` | 20,000 | **3,001** | 검색창 비우고 Enter | **20,000** |
| KQL | `price >= 100000` | 20,000 | **8,088** | 검색창 비우고 Enter | **20,000** |

세 값 모두 Dev Tools 실측값(`3,001` / `8,088`)과 일치했다.

**두 조건에서 관찰한 것**

- `in_stock : false` (3,001건) — Donut이 `false 3,001 (100%)` **한 조각만** 남았다.
  반면 카테고리 Bar는 **8개가 그대로** 남았고 값이 343~406으로 고르다.
  **재고 없는 상품이 특정 카테고리에 쏠려 있지 않다**는 뜻이다. 재입고 우선순위를 카테고리로 가를 근거가 없다.
- `price >= 100000` (8,088건) — 카테고리 Bar가 **5개로 줄었다**(전자기기 약 2,020 / 생활 1,700 / 스포츠 1,560 / 패션 1,400 / 반려동물 1,400).
  도서·뷰티·식품이 사라졌는데, 세 카테고리의 가격 상한이 각각 48,000 / 89,000 / 74,000원이라
  **10만 원 이상 상품이 존재할 수 없기 때문**이다. 4교시에서 저가 구간이 컸던 이유와 같은 구조다.
  재고 비율도 `true 6,862 (84.84%)`로 전체 85%와 거의 같아, **가격대와 재고 상태는 무관**해 보인다.

- 세 방식의 사용자가 느끼는 차이:
  - **Control** — Dashboard 위에 붙박이 선택기로 있어 **무엇을 바꿀 수 있는지 사용자가 미리 안다.**
    값 목록을 보여 주므로 오타가 없고, `Any`로 되돌리는 방법도 한눈에 보인다. 자주 바꾸는 조건에 맞다.
  - **Filter** — 상단 pill로 남아 **지금 무슨 조건이 걸려 있는지 명시적으로 보인다.**
    잠시 끄기(`Temporarily disable`), 반대로 뒤집기(`Exclude results`)가 가능해 특정 조건을 유지·전환할 때 좋다.
  - **KQL** — 문법을 알아야 하지만 여러 조건을 한 줄로 빠르게 조합할 수 있다.
    반면 **화면에 조건이 문자열로만 남아** 협업자가 의도를 파악하기 어렵고 오타가 곧 0건으로 이어진다.
  - 세 방식 모두 **문서를 지우지 않고 보여 줄 대상만 제한한다**는 점은 같다.
- 모든 조건 제거 후 전체값: **20,000** (현재 상태 — Control `Any`, filter pill 없음, KQL 비어 있음)
- `Filter for value` 문구가 없을 때 확인한 filter pill과 변한 패널: 이번에는 KQL 입력으로 조건을 걸어
  filter pill을 만들지 않았다. 다만 KQL도 pill과 마찬가지로 **여러 패널이 동시에 바뀌는지**로 적용 여부를 판단했다.
  차트 막대를 클릭했을 때 버전에 따라 팝업 없이 곧바로 filter가 붙을 수 있으므로,
  문구를 기다리지 말고 **상단에 pill이 생겼는지와 여러 패널 값이 함께 바뀌었는지**로 판단한다.
- 캡처 파일: `p05-q02-control-applied.png`(Control), `p05-q03-filter-instock-false.png`(3,001),
  `p05-q03-kql-price.png`(8,088), `p05-q03-control-reset.png`(전체 해제 20,000)
